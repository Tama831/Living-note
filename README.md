# 🌱 Living-note — 生きたノート

**Declare a topic — papers gather themselves, and one Markdown note keeps re-weaving itself.**
**関心を宣言すると、論文が自分で集まり、1枚のノートが編み直され続ける。**

Living-note is a tiny toolbox for running a personal-scale *living review* of the medical literature.
Living-note は、医学文献の「生きたレビュー」を個人サイズで回すための小さな道具箱です。

- Declare an interest area as a one-line search query (e.g. appendicitis)
- Once a week, new PubMed arrivals are collected automatically (keyless API, stdlib-only Python)
- An AI (the *weaver*) **rewrites the whole note** — not an ever-growing list, but a five-line
  summary and a cross-cutting synthesis that always reflect the current state
- When you want the actual papers, only **legal open-access full texts** are fetched and stored locally
- Notes are plain Markdown — drop them into NotebookLM for cited Q&A, or paste into any AI chat

<!-- -->

- 関心領域を1行の検索式で宣言する (例: 虫垂炎)
- 週1回、PubMed の新着を自動収集する (無認証 API・鍵不要・Python 標準ライブラリのみ)
- AI (織り手) がノート全体を**編み直す** — 追記の羅列ではなく、頭の「5行サマリ」と
  テーマ別の「横断まとめ」が常に現在地を映す
- 本文が読みたくなったら、**合法なオープンアクセス全文だけ**を取得してローカルに貯める
- ノートはただの Markdown — NotebookLM に入れれば引用付き Q&A、AI チャットに貼れば相談相手になる

> **The 30-second story**: a note seeded with 3 library papers was given its first run — it pulled
> 30 new arrivals from the last 180 days and, 12 minutes later, had grown into a 33-paper
> synthesis: where POCUS fits, the pediatric "are antibiotics even needed?" debate, the shifting
> rationale for interval appendectomy, all woven in.
>
> **30秒ストーリー**: 蔵書3本の虫垂炎ノートに初回実行をかけたところ、直近180日の新着30本が
> 集まり、12分後には33本構成の横断まとめに自動成長しました。POCUS の使いどころ、小児の
> 「抗菌薬は本当に要るか」論争、interval appendectomy の判断軸の移動まで編み込まれた状態で、です。

## 🚀 Quickstart — reproduce from zero / クイックスタート (ゼロから再現する手順)

### 0. What you need / 必要なもの

| Item / 項目 | Purpose / 用途 | How to get it / 入れ方 |
|---|---|---|
| Python 3.10+ | collector script, no extra libraries / 収集スクリプト (追加ライブラリ不要) | usually preinstalled on macOS/Linux: `python3 --version` |
| LLM CLI (optional / 任意) | automating the weave / 織りの自動化 | e.g. [Claude Code](https://claude.com/claude-code). **Works without one** — see step 4 / **無くても動く** (手順4)。Options & real costs / 選択肢と費用の実際: [docs/operations.md](docs/operations.md) |
| pdftotext (optional / 任意) | full-text layer / 全文レイヤー | macOS: `brew install poppler` / Ubuntu: `sudo apt install poppler-utils` |

### 1. Clone and declare your interest / 取得して、関心を宣言する

```bash
git clone https://github.com/Tama831/Living-note.git
cd Living-note
cp config/living-notes.example.json config/living-notes.json
cp notes/template.md notes/my-topic.md      # English notes: use notes/template.en.md
```

Open `config/living-notes.json` and edit `topics` to match your interests (the four samples are
in there — copying one and changing the query is enough). Queries use PubMed syntax; a good
starting shape is `<disease>[Title] AND (systematic[sb] OR guideline[pt] OR randomized controlled trial[pt] OR review[pt])`.

`config/living-notes.json` を開き、`topics` を自分の関心に書き換えます (サンプル4本の設定が
そのまま入っているので、真似して1個足すだけでもOK)。検索式は PubMed の記法です — まず
`<病名>[Title] AND (systematic[sb] OR guideline[pt] OR randomized controlled trial[pt] OR review[pt])` から始めるのがおすすめ。

### 2. Dry run — nothing is written / 素振り (何も書き込まずに確認)

```bash
python3 scripts/living_notes_update.py --dry-run --force
```

Output like this means success / こんな出力が出れば成功です:

```
[my-topic] 検索窓 2026/02/08→2026/08/07: hits=30 新規候補=25 (上限超過で5件を次回送り)
  - 42384223 Evidence map of appendicitis - a living systematic review with meta-analyses.
  ...
```

`新規候補=0` means your query is too narrow (→ Troubleshooting below).
`新規候補=0` なら検索式が狭すぎます (→ 下の「困ったとき」)。

### 3. First real run / 初回実行

```bash
python3 scripts/living_notes_update.py --topic my-topic --force
```

(Dropping `--topic` also updates the four bundled samples — each weave takes a few minutes, so
start with just your own topic. / `--topic` を外すと同梱サンプル4本も更新されます — 織りは
1本あたり数分かかるので、まずは自分のトピックだけで試すのがおすすめ)

New papers land in the arrivals log with ⏳; if an LLM CLI is available the weave runs
immediately and the summary, synthesis and bibliography are rewritten (⏳→✅).
新着がノートの「🆕 新着ログ」に ⏳ 付きで入り、LLM CLI があればそのまま織りが走って
5行サマリ・横断まとめ・文献リストが書き上がります (⏳→✅)。

### 4. Weaving without an LLM CLI / LLM CLI が無い場合の織り (手動)

```bash
python3 scripts/living_notes_update.py --force --no-weave
python3 scripts/living_notes_update.py --print-weave-prompt my-topic
```

Paste the printed prompt into ChatGPT / Claude / Gemini and overwrite the note with the returned
Markdown — that *is* the weave.
出てきたプロンプトを ChatGPT / Claude / Gemini に貼り、返ってきた Markdown でノートを
上書きすれば、それが「織り」です。

### 5. Then leave it alone / あとは放っておく

```bash
python3 scripts/living_notes_update.py            # call daily — the 7-day gate makes it weekly / 毎日呼んでOK、週1回だけ動く
python3 scripts/living_notes_update.py --status   # state check / 状態確認
python3 scripts/living_notes_update.py --sleep my-topic   # 🛏️ pause (the note remains) / 休止 (ノートは残る)
python3 scripts/living_notes_update.py --wake  my-topic   # 🟢 resume / 再開
```

cron / launchd registration examples and the full-text layer (`UNPAYWALL_EMAIL`) are in
[docs/setup.md](docs/setup.md), ready to paste.
cron / launchd への登録例と全文レイヤーの設定は [docs/setup.md](docs/setup.md) に
そのまま貼れる形で置いてあります。

### Verified environments / 検証済み環境 (2026-08-07)

- **macOS (dev machine)** — all steps + weave (Claude Code) + full-text layer / 全手順+織り+全文レイヤー
- **Clean Debian 12 LXC** — apt prerequisites → clone → 22 tests → dry run → collection → real cron
  registration & firing → `weave_command` swap, end to end / まっさらの新規コンテナで apt 前提→clone→テスト22本→素振り→収集→cron 実発火→織り手差し替えまで通し確認

## How it works / しくみ

```
declare interests (config)              ┌── 🛏️ --sleep pauses anytime (note remains)
関心の宣言                               │      いつでも停止 (ノートは残る)
   │                                    │
   ▼        7-day gate / 7日ゲート       │
PubMed arrivals ──→ dedupe vs your library ──→ appended to arrivals log (⏳)
新着収集             蔵書と重複判定             新着ログに追記
                                                     │
                     the weaver (LLM) rewrites the whole note (⏳→✅); fails soft — collection survives
                     織り手がノート全体を編み直す (⏳→✅)。失敗しても収集分は残る (fail-soft)
                                                     │
                                                     ▼
                    📌 five-line summary / 🧵 synthesis / 📚 bibliography updated
                    📌 5行サマリ / 🧵 横断まとめ / 📚 文献リスト が更新される
                                                     │
        (optional) legal-OA full texts → local store → "answer from my corpus"
        (任意) 合法OA全文 → ローカル全文ストア → 「その中から解答」
```

## 🔗 Connect your reference manager / 自分の文献管理ツールとつなぐ (Paperpile / Zotero)

Drop a BibTeX export of your library into the repo and Living-note connects to **your own
collection**. Making the export — Paperpile: select papers → Export → BibTeX / Zotero: File →
Export Library → BibTeX. Put the .bib somewhere like `library/my-library.bib` and register it in
`dedupe_sources`.

手持ちの文献リスト (BibTeX export) を置くと、Living-note は**あなたの蔵書**とつながります。
export の作り方 — Paperpile: 論文を選択 → Export → BibTeX / Zotero: File → Export Library →
BibTeX。できた .bib を `library/my-library.bib` などに置き、config の `dedupe_sources` に登録します。

Each topic can then choose one of three modes (`"mode"`):
つながると、トピックごとに**3つのモード**が選べます:

| mode | What it does | 何をするか |
|---|---|---|
| `latest` (default / 既定) | weave from new PubMed arrivals | PubMed の新着を集めて織る —「最新の知見を中心に」 |
| `library` | weave **only from papers you collected**; PubMed is not queried | **自分が集めた蔵書の中だけ**から該当分を拾って織る |
| `both` | fusion — your library as the foundation, arrivals woven on top | 融合 — 蔵書を土台に、新着がその上に編み込まれていく |

```json
{
  "dedupe_sources": ["library/my-library.bib"],
  "topics": [
    {
      "slug": "appendicitis",
      "title": "虫垂炎",
      "mode": "both",
      "library_query": "appendicitis|appendix",
      "queries": ["appendicitis[Title] AND (systematic[sb] OR review[pt])"],
      "note": "notes/appendicitis.md"
    }
  ]
}
```

- `library_query` selects from your library (case-insensitive regex over titles + keywords). Write
  it in English for English-language papers. / 蔵書から拾う条件 (正規表現)。英語文献には英語で
- `dedupe_sources` also works in `latest` mode: papers already in your library are never
  re-imported. / `latest` モードでも有効 — 蔵書済みの論文は新着として二重取り込みしない
- Library-sourced entries are labeled 「蔵書より」 in the log. / 蔵書由来はログで区別が付きます
- Honest caveat: the .bib is a **manual export** — refresh it occasionally after adding papers
  (reference managers expose no public API yet). / 正直な注意: .bib は**手動 export** です — 論文を足したらたまに export し直してください (管理ツール側に公開 API がまだ無いための制約)

## 🔧 Troubleshooting / 困ったとき

| Symptom / 症状 | Fix / 対処 |
|---|---|
| `新規候補=0` (no candidates) | widen the query (`[Title]` → `[Title/Abstract]`), raise `initial_lookback_days` to 365 / 検索式を広げる (`[Title]`→`[Title/Abstract]`)、`initial_lookback_days` を 365 に |
| Too many noisy hits / ヒットが雑音だらけ | narrow to `[Title]`, filter types with `AND (systematic[sb] OR guideline[pt] ...)` / 種別で絞る |
| ⏳ never becomes ✅ (no weave) | no LLM CLI found — weave manually via `--print-weave-prompt`, or set `weave_command` / 手動織りか CLI 設定 |
| Weave output was discarded / 織りが捨てられた | by design — output failing validation (missing anchors etc.) is rejected; collection survives and re-weaves next run / 仕様です。収集分は残っています |
| NotebookLM won't take the .md | paste the content into a Google Doc and add that as the source / Googleドキュメント経由で同じ効果 |
| Full text unavailable (`no_oa`) | it's paywalled — a legitimate limit. OA rates run 30–70% by field / ペイウォール内 = 正当な限界。OA 率は分野により3〜7割 |

## Design principles / 設計原則

- **One library, notes as views** — knowledge is never siloed per notebook; the corpus is one pool
  and each note is a window onto it. / **単一の蔵書 + ビューとしてのノート** — 情報がノートブック単位で分断されない
- **Legal OA only** — full texts come exclusively via Unpaywall; no paywall circumvention.
  / **合法 OA のみ** — ペイウォール迂回はしない
- **Fail-soft** — an API or LLM failure never takes the scheduled run down with it; collected data
  always survives. / **fail-soft** — 外部の失敗が定期実行を道連れにしない
- **Letting go loses nothing** — `--sleep` stops collection, but the note lives on as a document.
  / **降ろしても失われない** — 収集は止まってもノートは読み物として生き続ける
- **Just Markdown** — no lock-in; readable by any AI, any editor, and yourself ten years from now.
  / **ただの Markdown** — ロックインなし。どの AI にも、どのエディタにも、10年後の自分にも読める

## ⚠️ Medical disclaimer / 医療情報についての断り

Notes generated by this tool are **AI summaries of the literature, not medical advice**. They may
contain errors. Clinical decisions must rest on the original papers, guidelines, and the judgment
of clinicians on the ground. Every claim in a note links to its source — the ability to reach the
original is what you should trust, not the summary itself.

このツールが生成するノートは **AI による文献要約であり、医学的助言ではありません**。誤りが
含まれえます。臨床判断は必ず原著論文・ガイドライン・各現場の判断に基づいてください。ノート内の
全記述には出典リンクが付きます — 「原文に当たれること」を信頼性の根拠にしてください。
