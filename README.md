# 🌱 Living-note

![living heartbeat](https://img.shields.io/endpoint?url=https%3A%2F%2Fraw.githubusercontent.com%2FTama831%2FLiving-note%2Fmain%2Fdata%2Fheartbeat.json)

> 🇯🇵 日本語版はこちら → **[README.ja.md](README.ja.md)**

**Declare a topic — papers gather themselves, and one Markdown note keeps re-weaving itself.**

Living-note is a tiny toolbox for running a personal-scale *living review* of the medical literature.

- Declare an interest area as a one-line search query (e.g. appendicitis)
- Once a week, new PubMed arrivals are collected automatically (keyless API, stdlib-only Python)
- An AI (the *weaver*) **rewrites the whole note** — not an ever-growing list, but a five-line
  summary and a cross-cutting synthesis that always reflect the current state
- When you want the actual papers, only **legal open-access full texts** are fetched and stored locally
- Notes are plain Markdown — drop them into NotebookLM for cited Q&A, or paste into any AI chat

> **The 30-second story**: a note seeded with 3 library papers was given its first run — it pulled
> 30 new arrivals from the last 180 days and, 12 minutes later, had grown into a 33-paper
> synthesis: where POCUS fits, the pediatric "are antibiotics even needed?" debate, the shifting
> rationale for interval appendectomy, all woven in.

**How the 🫀 live rows update (auto-sync)**: the author's running instance collects new PubMed
arrivals once a week, reweaves each note, and pushes the result straight to this repo — plus a
heartbeat commit even on zero-news weeks, so "no update" and "dead" are distinguishable from the
outside. The commit history itself is proof the notes are alive; the badge above shows the last
check date. The GLP-1 note is deliberately a fast-moving field: its first sweep found ~100
eligible papers in 180 days (25 collected, 75 carried over), so you can watch the mechanism
digest a backlog week by week.

The coffee note is a **hand-woven bonus** ☕ — no PubMed collection, just the note format applied
to a hobby, updated when the author asks for a reweave. Proof that the living-note shape works
for any interest, not only medicine.

## Two doors

### 🚪 Door 1: no code required (clinicians & researchers)

If you have the note (.md), you don't need this toolbox. Download a sample above, add it as a
source in [NotebookLM](https://notebooklm.google.com/), and ask questions in your language —
answers come back with citation jumps, and notebooks can be shared with colleagues by link.
→ **5-minute guide: [docs/notebooklm-guide.md](docs/notebooklm-guide.md)**

### 🚪 Door 2: run it yourself

Follow the quickstart below. If you use Claude Code, this repository also works as a plugin
(`/living-note` — [skills/living-note/SKILL.md](skills/living-note/SKILL.md)).

## 🚀 Quickstart — reproduce from zero

### 0. What you need

| Item | Purpose | How to get it |
|---|---|---|
| Python 3.10+ | collector script, no extra libraries | usually preinstalled on macOS/Linux: `python3 --version` |
| LLM CLI (optional) | automating the weave | e.g. [Claude Code](https://claude.com/claude-code). **Works without one** — see step 4. Options & real costs: [docs/operations.md](docs/operations.md) |
| pdftotext (optional) | full-text layer | macOS: `brew install poppler` / Ubuntu: `sudo apt install poppler-utils` |

### 1. Clone and declare your interest

```bash
git clone https://github.com/Tama831/Living-note.git
cd Living-note
cp config/living-notes.example.json config/living-notes.json
cp notes/template.md notes/my-topic.md      # Japanese notes: use notes/template.ja.md
```

Open `config/living-notes.json` and edit `topics` to match your interests (the four samples are
in there — copying one and changing the query is enough). Queries use PubMed syntax; a good
starting shape is
`<disease>[Title] AND (systematic[sb] OR guideline[pt] OR randomized controlled trial[pt] OR review[pt])`.

### 2. Dry run — nothing is written

```bash
python3 scripts/living_notes_update.py --dry-run --force
```

Output like this means success:

```
[my-topic] window 2026/02/08->2026/08/07: hits=30 new candidates=25 (25-cap overflow: 5 carried to next run)
  - 42384223 Evidence map of appendicitis - a living systematic review with meta-analyses.
  ...
```

`new candidates=0` means your query is too narrow (→ Troubleshooting below).

### 3. First real run

```bash
python3 scripts/living_notes_update.py --topic my-topic --force
```

(Dropping `--topic` also updates the four bundled samples — each weave takes a few minutes, so
start with just your own topic.)

New papers land in the arrivals log with ⏳; if an LLM CLI is available the weave runs
immediately and the summary, synthesis and bibliography are rewritten (⏳→✅).

### 4. Weaving without an LLM CLI

```bash
python3 scripts/living_notes_update.py --force --no-weave
python3 scripts/living_notes_update.py --print-weave-prompt my-topic
```

Paste the printed prompt into ChatGPT / Claude / Gemini and overwrite the note with the returned
Markdown — that *is* the weave.

### 5. Then leave it alone

```bash
python3 scripts/living_notes_update.py            # call daily — the 7-day gate makes it weekly
python3 scripts/living_notes_update.py --status   # state check
python3 scripts/living_notes_update.py --sleep my-topic   # 🛏️ pause (the note remains)
python3 scripts/living_notes_update.py --wake  my-topic   # 🟢 resume
```

cron / launchd registration examples and the full-text layer (`UNPAYWALL_EMAIL`) are in
[docs/setup.md](docs/setup.md), ready to paste.

### Verified environments (2026-08-07)

- **macOS (dev machine)** — all steps + weave (Claude Code) + full-text layer
- **Clean Debian 12 LXC** — apt prerequisites → clone → tests → dry run → collection → real cron
  registration & firing → `weave_command` swap, end to end
- **Weaver compatibility** — both `claude -p` (default) and a Gemini wrapper produced valid
  weaves; when output fails validation, collected data is preserved (fail-soft). A local Gemma
  was also measured — see [docs/operations.md §4](docs/operations.md)

## How it works

```
declare interests (config)              ┌── 🛏️ --sleep pauses anytime (note remains)
   │                                    │
   ▼        7-day gate                  │
PubMed arrivals ──→ dedupe vs your library ──→ appended to arrivals log (⏳)
                                                     │
                     the weaver (LLM) rewrites the whole note (⏳→✅);
                     fails soft — collection always survives
                                                     │
                                                     ▼
                    📌 five-line summary / 🧵 synthesis / 📚 bibliography updated
                                                     │
        (optional) legal-OA full texts → local store → "answer from my corpus"
```

## 🔗 Connect your reference manager (Paperpile / Zotero)

Drop a BibTeX export of your library into the repo and Living-note connects to **your own
collection**. Making the export — Paperpile: select papers → Export → BibTeX / Zotero: File →
Export Library → BibTeX. Put the .bib somewhere like `library/my-library.bib` and register it in
`dedupe_sources`.

Each topic can then choose one of three modes (`"mode"`):

| mode | What it does |
|---|---|
| `latest` (default) | weave from new PubMed arrivals |
| `library` | weave **only from papers you collected**; PubMed is not queried |
| `both` | fusion — your library as the foundation, arrivals woven on top |

```json
{
  "dedupe_sources": ["library/my-library.bib"],
  "topics": [
    {
      "slug": "appendicitis",
      "title": "Appendicitis",
      "mode": "both",
      "lang": "en",
      "library_query": "appendicitis|appendix",
      "queries": ["appendicitis[Title] AND (systematic[sb] OR review[pt])"],
      "note": "notes/appendicitis.md"
    }
  ]
}
```

- `library_query` selects from your library (case-insensitive regex over titles + keywords)
- `dedupe_sources` also works in `latest` mode: papers already in your library are never re-imported
- Library-sourced entries are labeled "from library" in the arrivals log
- Honest caveat: the .bib is a **manual export** — refresh it occasionally after adding papers
  (reference managers expose no public API yet)

## 🔧 Troubleshooting

| Symptom | Fix |
|---|---|
| `new candidates=0` | widen the query (`[Title]` → `[Title/Abstract]`), raise `initial_lookback_days` to 365 |
| Too many noisy hits | narrow to `[Title]`, filter types with `AND (systematic[sb] OR guideline[pt] ...)` |
| ⏳ never becomes ✅ (no weave) | no LLM CLI found — weave manually via `--print-weave-prompt`, or set `weave_command` |
| Weave output was discarded | by design — output failing validation (missing anchors etc.) is rejected; collection survives and re-weaves next run |
| NotebookLM won't take the .md | paste the content into a Google Doc and add that as the source |
| Full text unavailable (`no_oa`) | it's paywalled — a legitimate limit. OA rates run 30–70% by field |

## Design principles

- **One library, notes as views** — knowledge is never siloed per notebook; the corpus is one pool
  and each note is a window onto it
- **Legal OA only** — full texts come exclusively via Unpaywall; no paywall circumvention
- **Fail-soft** — an API or LLM failure never takes the scheduled run down with it; collected data
  always survives
- **Letting go loses nothing** — `--sleep` stops collection, but the note lives on as a document
- **Just Markdown** — no lock-in; readable by any AI, any editor, and yourself ten years from now

Why this shape (with a 14-tool prior-art table): [docs/design.md](docs/design.md)

## ⚠️ Medical disclaimer

Notes generated by this tool are **AI summaries of the literature, not medical advice**. They may
contain errors. Clinical decisions must rest on the original papers, guidelines, and the judgment
of clinicians on the ground. Every claim in a note links to its source — the ability to reach the
original is what you should trust, not the summary itself.
